# メインメニュー（ui/main_window.py）

2026-10-09 のコメント軽量化で、コメント・docstring から移した内容。関数名で参照する。
DB の切替・新規作成・削除・バックアップ・復元の手順は `docs/db.md`。

## 起動時（`MainWindow.__init__()`）

- 前回選んでいた DB（`app_settings.json`）があれば切り替える。無ければ既定DB（`APP_DATA_DIR/db/inventory.db`）のまま。記憶したパスが今は存在しない（削除・共有フォルダが使えない等）なら、既定DB で起動を続け、UI を作り終えてから知らせる（途中でダイアログが割り込まないように）
- 既定DB（未選択）の間は、ロックファイルにも一切触れない。D-56・D-57 の「既定DB は読み書きしない」方針を `.lock` にも広げた（D-59）。既定DB に古いロックが残っていても起動できる。`_lock_acquired` は False のままなので、ハートビートと解放も何もしない
- 既定DB 以外でロックを取れなければ、ほかの PC・利用者が使用中とみなして起動を中断する。LoginWindow は `winfo_exists()` を見てから `mainloop()` を呼ぶ（破棄済みのルートで mainloop しないため）
- ロックのハートビートは5分ごと。30分（`LOCK_STALE_SECONDS`）更新が無いロックは自動解除の対象になるので、それを防ぐ
- 閉じるとき（×・Alt+F4）は `_on_app_close()` でロックを解放する。`on_logout()` は destroy() を直接呼ぶのでこのハンドラを通らず、個別に解放する
- topmost は明示的に False にしている（以前 True が設定されていた影響を避けるため）。メインメニューはフォーカス制御（lift/focus_force/grab_set）をしない

## ウインドウサイズ

- 幅 1020px: 「データベース選択」行（db_select_frame）の必要幅が実測 986px（admin/operator・未選択/選択後/在庫値出力済み警告のどれでも同じ）で、以前の 940px では 46px 見切れていた（§20.9 の申し送り、2026-10-07 解消）。986px ぎりぎりだと文言やフォントの差で再び見切れるので、ボタン間の隙間と同程度の 34px を足した
- 高さ 620px: 生産面マスターを追加して（2026-10-07）admin 表示の必要高さが 599px になり、600px まで残り1px だったので、余裕を持たせた
- 接続中の DB パスのラベルの最大描画幅 `_DB_PATH_LABEL_MAX_WIDTH_PX = 680`: ウインドウ幅 940px 当時に、接頭辞ラベル（Helvetica 9 で約135px）・左右の余白・枠を引いて決めた安全側の値
- パスの省略（`_truncate_path_for_display()`）は文字数ではなくピクセル幅で判定する。共有フォルダの UNC パスには日本語のフォルダ名（半角の約2倍の幅）が多く、文字数で切るとはみ出した（実測で確認）。先頭（ドライブ・サーバー名）と末尾（フォルダ名・ファイル名。どの DB かを見分けるのに一番大事）を残し、長い方から1文字ずつ削る

## メニューの配置

- 左＝共通マスタ（`config.MASTER_DB_PATH`。DB を切り替えても変わらない）、右＝月次データ（`config.DB_PATH`）。マスタDB 分離の経緯は D-38・D-42
- 左の末尾の「ツール」（PDF読み取り・操作履歴）は例外で、月次DB（inventory_stock・operation_log）を使う。使用頻度の低い補助機能をまとめた配置上の都合（D-50）。以前は月次データ側の8・9番だった。番号は付けない
- 生産面マスター（2026-10-07）は、構成基板数マスター・基板丁数マスターと同じくロールを問わず表示する。これに伴い「新規アカウント登録」を3→4、「アカウント管理」を4→5に変えた
- 新規アカウント登録（ロールを問わず表示）: ログイン画面と同じ画面を、ログイン後にも開けるようにした（2026-10-03）
- アカウント管理と「マスタデータを他PCから取り込む」は admin にだけ表示する（operator ではボタン自体を作らない）。マスタの取り込みは workers（ログインできる作業者と役割）に他の PC の admin・operator が追加されうるので、作業者管理と同じ基準にした。`on_merge_master_from_backup()` 自体でも admin かを確認する（直接呼ばれた場合への備え）
- PDF読み取りは常に無効（D-85、2026-10-06）。ボタン・コマンド・機能のコードは削除せずに残す。一括の有効化/無効化の対象リストに入れないので、DISABLED が保たれる
- ログアウトボタンは誤操作を避けるため、全幅にせず半分程度の幅で中央に置く
- 「バックアップの呼び出し」（D-50）: 以前は「共有フォルダの DB を開く」機能をバックアップの復元に使っていた（旧D-45）が、原本がそのまま本番 DB になる・マスタDB は復元されない・D-20（ローカル＋バックアップ方針）と合わない、の3点の問題があったので、新しいフォルダにコピーしてから切り替える方式に置き換えた。権限の制限は無い

## ボタンの有効・無効

- 2つのゲートを `_apply_widget_states()` で合成する
  - `_menu_widgets`: 一括無効化（`_set_menu_enabled()`）。前月引き継ぎ（`carry_over_incomplete_lots()`）の実行中は `config.DB_PATH` が旧DB と新DB の間で一時的に入れ替わるので、ほかの画面を開いたり DB を切り替えたりさせない
  - `_default_db_locked_widgets`: 既定DB（未選択）の間に無効にする業務ボタン（D-56・D-57）。名前の無い DB に気づかず入力するのを防ぐ。DB の選択・新規作成・削除・バックアップの呼び出し・ログアウトは、既定DB の間も使えるので入れない
- どちらも「True なら制限なし」で持ち、AND で合成する。一方の解除（例: 引き継ぎ完了）で、もう一方の理由で無効のままにすべきボタンを有効にしてしまわないため
- `_default_db_locked_widgets` に入れたものは、必ず `_menu_widgets` にも入れる
- `db_folder_combobox` は readonly/disabled で切り替える（ttk.Combobox を NORMAL にすると自由入力になる）
- 前月引き継ぎのチェック（`chk_carry_over`）は個別に扱う。既定DB の間は「新しいデータベースを作成」は使えるが、このチェックは使えなくし、チェックも外す（既定DB を引き継ぎ元にした不定な動作を防ぐ）

## 在庫値出力済みの警告（D-58）

- 在庫値を出力済みの DB を開いている間は、パスの直下に警告を出す。警告だけで、入力は妨げない
- 月次データに書き込む画面（1〜6）を開く前には確認ダイアログを出す（`_confirm_proceed_despite_exported_db()`）。在庫値出力（7）自体・閲覧系・ツール・共通マスタ・DB 管理は対象外
- 既定DB には `get_inventory_diff_export_status()` を呼ばない。内部の `init_operation_log_table()`（CREATE TABLE IF NOT EXISTS）で、存在しない DB ファイルが作られてしまう
- `_update_current_db_label()` は、DB の選択状態か在庫値出力済み状態が変わりうる操作の後に必ず呼ぶ（起動時、`_try_switch_db_path()`、新規作成の両方の分岐、ローカル DB の削除後）。ボタンの状態と警告をまとめて再評価する入口

## 画面の開き方

- 多重表示の防止（`_open_singleton_window()`）: 開いていれば前面に出すだけ。各画面クラスには手を入れず、外から WM_DELETE_WINDOW のハンドラを設定して、閉じたら `_open_windows` から外す
- 生産実績入力画面（`open_kitting_production_entry()`）: 計画一覧の取得が重く、UI スレッドで行うとロード画面も描画されずフリーズしたように見えるので、別スレッドで取得してから画面を作る。非同期なので `_open_singleton_window()` は使えない。開いていれば前面に出して `load_plan_list()` で更新する。読み込み中に再度呼ばれたら、`_kitting_entry_loading` でスレッドを二重に起こさない。`on_ready` は、以前メインメニューにあった「実績CSV取込状況」ボタン用で、今は使う呼び出し元が無い
- 在庫差異レポート（`open_inventory_diff()`）: 開く前に NG一覧・仕掛一覧の未処理（未展開・未確定で、対象外にしていないもの）を数え、残っていれば確認する。注意喚起だけ
- ログアウト: 子ウインドウは、親（MainWindow）を destroy() すれば Tkinter の仕様で一緒に破棄される

## DB 操作まわりの細かい点

- 新しい DB の作成直後にロックを確認するのは念のため。失敗すると、新しい DB ファイルは作られたまま使われずに残る
- 前月引き継ぎでは、引き継ぎ元の DB パスを切り替えの前に確定させておく（処理中に config.DB_PATH が入れ替わるため）。新しい DB のテーブルは引き継ぎ処理の中で作られるので、`init_kitting_plan_tables()` は呼ばない
- 引き継ぎの完了時、`config.DB_PATH` はもう新しい DB なので、操作履歴は新しい DB に記録される（旧DB には書かない）
- 作成・削除・バックアップの呼び出しの履歴は、`log_operation()`（月次DB）に加えて master.db の db_lifecycle_log にも記録する（2026-10-06、D-87）。取り込み先の DB を後で消しても残る
- フォルダ名 "db" は、既定DB の判定（親フォルダ名が "db" か）とぶつかるので予約している
- 非同期の処理（引き継ぎ・バックアップ・マスタの取り込み）は、LoadingWindow＋threading.Thread(daemon=True)＋queue.Queue＋after(200) のポーリングで行い、実行中は DB 操作のボタンを無効にする
