# 実績レポート（日報・月報の統合、ui/unified_report_window.py）

2026-10-09 のコメント軽量化で、コメント・docstring から移した内容。関数名で参照する。
集計の中身（引落・仕掛・確認事項・警告）は `docs/domain/lot_completion.md`。

## 統合の経緯（2026-09-30〜10-01）

- 旧日報（DailyReportWindow）は、起動直後を除けば日付を変えるたびに `build_monthly_report(日付, 日付)` を呼んでいて、実質「1日だけの月報」だった
- 旧日報は `configure_status_color_tags()` を一度も呼んでおらず、「確認事項」の赤字・オレンジ字（needs_review/shortfall）が出ていなかった（隔離コピー上で、tag_configure の foreground が空のままであることを確認）。統合画面では `configure_lot_stripe_tags()` と合わせて必ず両方呼ぶ
- 期間を「今日/今週/今月/カスタム範囲」の4択にそろえ、どれも `build_monthly_report(from_date, to_date)` を呼ぶことで、上の2点を解消した
- 旧月報（ui/monthly_report_window.py の MonthlyReportWindow）は、全機能（仕掛数量抽出・警告3種の CSV 出力など）の移植を確認してから 2026-10-01 に削除した。警告ダイアログ5種・仕掛数量抽出・CSV 出力は、それまで両方の画面でロジックが重複していた
- 開いた直後は「今日」で集計する（旧日報・月報も、開いた直後に何かしらの一覧を出していた）

## 期間（`compute_period_dates()`）

- 週は月曜から（ISO 8601・`datetime.weekday()` に合わせた）。業務で日曜起算が使われていないか、「今週」の終わりをまだ来ていない日曜まで含めるべきかは判断できていない
- 終了日は、週・月の理論上の終わり（日曜・月末）ではなく今日にする。実績の日付は今日までしか無いので結果は同じだが、タイトルにまだ来ていない日付が出ると誤解を招くため
- カスタム範囲に切り替えたときは、日付を変えない（直前に見ていた範囲を残す）

## 警告のオン/オフ（2026-10-01）

- 警告5種を `warning_toggle_vars`（既定はすべてオン。月報は常に全部出していた挙動を変えない）で切り替える
- `_build_report_rows()` は5種をまとめて1回で判定していて、1種だけを外す作りになっていない。計算は軽い（既存のベンチマークで1ロットあたり数 ms）ので、計算は常に全部行い、オフの警告はダイアログを出さないだけにした
- 警告の CSV 出力ボタン（マスタ未登録・構成基板数超過・構成基板数不一致）は、オン/オフと関係なく常に使える。チェックボックスは「集計のたびにダイアログで知らされたくない」という表示の好みで、「その異常を今後気にしない」という意味ではないため。例えば件数が多い既知の問題（マスタ未登録など）を毎回ダイアログで見たくはないが、整備の進み具合を確かめるために時々 CSV で出したい、という使い方を妨げない。対象が無ければ「対象がありません」と案内する
- 実績修正の後の読み直し（`refresh_report()`）で再表示する警告は、面1・面2の不整合だけ（発注数の不一致やマスタ未登録は、片面の修正では変わらない）。絞り込み条件は残す

## 行の絞り込み（2026-10-01）

- NG一覧・仕掛一覧と同じ「テキスト部分一致＋チェックボックス式ポップアップ」。軸はロットNo.（部分一致）・状態（一致/不足/超過/未登録/構成基板数不一致）・NGの有無（あり/なし）
- 「状態」と「NGの有無」は Treeview の列には出さない（「確認事項」と同じく、色分けと CSV/PDF 出力だけで表す既存の方針）
- 状態は `_build_report_rows()` の各行の status を、`ui.lot_progress_window.STATUS_LABELS` と同じ日本語に変えて使う。NG の有無は has_ng（NG 実績か NG 申告があるか）をそのまま使う。絞り込み用の表示キー（status_label・ng_label）は CSV/PDF 出力には使わない
- 絞り込みは `report_rows`（全件）を Python 側でふるい、絞り込み後の行だけを描き直す。ロット単位の縞模様は絞り込み後の行で計算し直す（消えた行の分だけ境目が変わるのは意図どおり）
- 絞り込み後にソートの順は保たれない（元の順で描き直す）。NG一覧・仕掛一覧・生産実績入力画面の計画一覧と同じ、アプリ全体で一貫した挙動（「フィルタ適用後にソートを再適用する機能は無い」と v1 の仕様として明記済み）

## 列の表示/非表示（2026-10-01）

- 列ヘッダーの右クリックで、チェック付きのメニューから表示する列を選ぶ。Treeview の displaycolumns だけを変え、columns は変えないので、CSV/PDF 出力は常に全列（画面では要らない列を隠しつつ、出力には漏れなく残せる）
- すべての列を隠すことはできない（最後の1列のチェックを外したら、すぐに戻す）
- report_date（登録日）は、REPORT_HEADERS 側で「確認事項」の直前（インデックス10）に足したので、`_cols` でも同じ位置に置く。見出しは `_cols` と REPORT_HEADERS を zip で対応させているので、順序がずれると見出しが1列ずつずれる

## ソート（`sort_by_column()`、2026-10-01）

- ロット進捗チェック画面と同じく、ロット単位のまとまりにしてからまとまりごとに並べ替える。ただしまとまりの作り方が違う
- ロット進捗チェックの一覧は、各ロットの実データ行の直後に「未確定」行が続くので、同じ lot_no の行は最初から連続している（連続した行をまとまりとして検出できる）
- この画面の行（`_build_report_rows()`）は実績の順に並び、「未確定」行は全ロット分を末尾にまとめて足すので、同じ lot_no の行が連続しているとは限らない。連続した行をまとまりにすると、同じロットが複数のまとまりに分かれ、「未確定」行がロットとまとまらない（隔離コピー上の実データで確認）
- そこで、lot_no が同じ行をすべて1つのまとまりに集める。まとまりの位置は、その lot_no が今の並びで最初に出た位置
- 数値として比べる列（`_NUMERIC_COLUMNS`）の board_count には「未登録」が入りうるので、変換に失敗したときのフォールバックを用意する（ロット進捗チェックと同じ）

## 仕掛数量抽出（`on_extract_wip()`）

- 対象のロットは、選択中の期間の `report_rows` に出てくる lot_no から決める（期間に依存する）
- 各ロットの状態（引落・仕掛・未生産、保存前の確認で見る needs_review）は、期間（report_date の範囲）に関係なく、今の実績・計画・構成基板数マスタから計算する（`calculate_lot_completion()`・`_evaluate_lot_status()` は report_date を引数に取らない）
- この2点の違いは旧月報でも同じで、移植による差は無い
